   الموقع نفسه (وهي CSP «تقرير فقط» اليوم: البند 2.9). الضوابط الفعلية للغلاف هي نطاق الصلاحيات وقائمة الأوامر، وقد ضُبطا. وُضعت CSP صارمة للصفحات
   المحلية استعداداً لصفحة «لا اتصال» داخل الغلاف.
2. **Service Worker لا يُمسح مخزونه عند الخروج** (كتبتها في 2.7 سابقاً): ما يخزّنه قشرة بلا بيانات، ومسحه يُفقد صفحة الدخول دون اتصال. المطلوب مسح
   **مخزن البيانات** عند الخروج حين يُبنى (وثيقة العمل دون اتصال 4.3)، لا القشرة.

### 0.3 المستودع والنسخ الاحتياطي (F-3، F-4)

- **اجعل المستودع خاصاً** إن لم يكن ضرورياً أن يكون عاماً. هذا يوقف المزيد من التسريب ويجعل Artifact النسخ الاحتياطي أقل خطراً، لكنه لا يمحو

### 0.4 خطة Supabase (N-15) — قرار منك

README يقول صراحة إن المشروع على **الخطة المجانية** («Supabase Free Tier لا يضمّن نسخاً احتياطية تلقائية»، والـ keepalive موجود لمنع الإيقاف عند الخمول).

- بوابة المستأجر: عمود انتهاء `portal_token_expires_at` (قرار 9.10: مثلاً 90 يوماً قابلة للتجديد، أو بلا انتهاء)، ودالة `rotate_portal_token` مع زر «تجديد الرابط»
  في ملف المستأجر، وسجل آخر دخول. والجدار الخارجي: قاعدة معدّل في Vercel Firewall على `/portal/*`.
- إعادة تعيين كلمة المرور: دالة `SECURITY DEFINER` مقصورة على `service_role` تُبطل جلسات المستخدم (يُتحقق من الواجهة الحالية في Supabase قبل التنفيذ)،
  يستدعيها `/api/admin/reset-password` بعد النجاح.

### 3.5 خط أساس للهجرات (من الخطة الرئيسية، القسم 11)

سحب مخطط الإنتاج كهجرة أساس واحدة وإصلاح 006 و035، حتى تعيد ملفات `supabase/migrations/` بناء الإنتاج حرفياً، وإضافة فحص انحراف في CI.
اليوم إعادة بناء القاعدة من المستودع تعطي نظاماً معطوباً (تسجيل الإيجار نفسه يفشل). يُنفَّذ **بعد** أن تستقر الهجرات 078–090 على الإنتاج.

## الملحق أ — استعلامات فحص الإنتاج (قراءة فقط)

شغّلها في Supabase → SQL Editor، كلها `SELECT`. الاستعلام 1 يبيّن ما طُبّق، و2–5 يقيسان حالة الأمان.

```sql
-- 1) أي الهجرات المقترحة مطبّقة؟ (true = موجودة أثرها)
SELECT
  EXISTS (SELECT 1 FROM pg_proc WHERE pronamespace = 'public'::regnamespace AND proname = 'charge_accrual_entry_date')      AS m078,
  to_regclass('public.payroll_runs') IS NOT NULL                                                                           AS m080,
  EXISTS (SELECT 1 FROM pg_proc WHERE pronamespace = 'public'::regnamespace AND proname = 'auth_role_may_write')            AS m081,
  to_regclass('migration_backup.m082_functions') IS NOT NULL                                                               AS m082,
  to_regclass('public.employee_leave_requests') IS NOT NULL                                                                AS m083,
  to_regclass('migration_backup.m085_functions') IS NOT NULL                                                               AS m085,
  to_regclass('migration_backup.m086_revoked') IS NOT NULL                                                                 AS m086,
  EXISTS (SELECT 1 FROM pg_proc WHERE pronamespace = 'public'::regnamespace AND proname = 'sync_rent_charges_to_schedule') AS m087;
-- 084 لا يُكتشف بوجود كائن جديد: نفّذ استعلام الفحص في رأس ملفها.

-- 2) دوال تنفّذها صلاحية anon (المطلوب بعد 085: صفر صفوف)
SELECT p.proname
FROM pg_proc p
WHERE p.pronamespace = 'public'::regnamespace
  AND has_function_privilege('anon', p.oid, 'EXECUTE');

-- 3) جداول وعروض يقرؤها anon (المطلوب بعد 078: لا شيء حساس)
SELECT c.relname, c.relkind
FROM pg_class c
WHERE c.relnamespace = 'public'::regnamespace
  AND c.relkind IN ('r', 'v', 'm')
  AND has_table_privilege('anon', c.oid, 'SELECT');

-- 4) سياسات كتابة مفتوحة (المطلوب بعد 078/086: 0)
SELECT count(*) AS open_write_policies
FROM pg_policies
WHERE schemaname = 'public'
  AND cmd IN ('INSERT', 'UPDATE', 'DELETE', 'ALL')
  AND (qual = 'true' OR with_check = 'true');

-- 5) الدور الافتراضي للحساب الجديد وهل يوجد اعتماد (يبيّن F-1)
SELECT pg_get_functiondef('public.handle_new_user'::regproc) AS handle_new_user_definition;
SELECT EXISTS (
  SELECT 1 FROM information_schema.columns
  WHERE table_schema = 'public' AND table_name = 'profiles' AND column_name = 'approved_at'
) AS profiles_has_approved_at;
```

## الملحق ب — ما نجح في الفحص (لا يحتاج عملاً)

- مسارات `/api/admin/invite` و`/api/admin/reset-password`: فحص الأصل ثم الهوية ثم الدور من القاعدة ثم الجسم؛ كلمة المرور 10–72؛ سجل تدقيق بالمعرّفات فقط.
- المقارنة بزمن ثابت لسر `keepalive`، وتحقق شكل رمز بوابة المستأجر قبل سؤال القاعدة، وترويسات الأمان (HSTS، COOP، Permissions-Policy، `no-store` على البوابة).
- إعادة التوجيه بعد الدخول محصورة بمسار داخلي (`safe-redirect.ts`)، وفلتر البحث `.or()` بلا حقن.
- معالجة التاريخ بتوقيت ليبيا وحساب نهاية الشهر بـ UTC: لا إزاحة يوم.
- لا `dangerouslySetInnerHTML` ولا `eval`، و`console.log` في 3 مواضع فقط.
- 41 فحصاً غير متصل و5 مجموعات اختبار على النسخة المعزولة (القسم 0) كلها ناجحة، وهي أساس بروتوكول «لا إفساد».
