### 3.2 السيناريوهات المدعومة بالكامل (وكل واحد له اختبار آلي)

| السيناريو | السلوك المطلوب |
|---|---|
| تحصيل شهر كامل | يُسدَّد الشهر، قيد التحصيل + الربط، سند قبض تلقائي |
| **تحصيل شهرين أو أكثر معاً** | توزيع على الأقدم أولاً؛ معاينة قبل الحفظ تُظهر كل شهر ومبلغه؛ أشهر مستقبلية = سداد مقدم يُطبَّق عند حلول الشهر |
| **نصف شهر — سداد جزئي** | الشهر «جزئي» بالمبلغ الصحيح؛ الدفعة التالية تكمل الباقي أولاً |
| **نصف شهر — إشغال جزئي** (دخول أو خروج منتصف الشهر) | احتساب تناسبي بعدد الأيام الفعلي (أو 30 يوماً — إعداد واحد للمول) مع إظهار عدد الأيام في المطالبة، كما يفعل Buildium |
| دفعة أكبر من المستحق | الفائض رصيد مقدم ظاهر في ملف المستأجر ويُطبَّق تلقائياً |
| دفعة لشهر مسدد | تُرفض برسالة واضحة، أو تُحوَّل رصيداً مقدماً باختيار صريح |
| تغيّر السعر منتصف العقد | شرائح السعر القائمة (تعمل) + زيادة سنوية مجدولة اختيارية |
| إعفاء كامل أو خصم جزئي | الإعفاء الكامل قائم؛ يضاف «خصم/تنازل» بمبلغ وسبب واعتماد (إشعار دائن) |
| شيك مرتجع | عكس الدفعة، إعادة فتح الأشهر، تنبيه، رسم اختياري |
| رسوم الخدمات المشتركة | مطالبة خدمات حسب المساحة (`area_sqm` موجود) أو مبلغ ثابت — بند `REV-SRV` |
| غرامة التأخير | اختيارية بقاعدة (نسبة/مبلغ بعد X يوم) ولا تُطبَّق إلا بعد تفعيلك |
| التأمين | استلام (التزام) واسترجاع أو خصم منه عند الإخلاء بقيد صحيح |
| ترتيب توزيع الدفعة | الأقدم أولاً افتراضياً، مع ترتيب مخصص حسب نوع المطالبة (إيجار ثم خدمات ثم غرامات) — نمط Buildium |

### 3.3 الواجهة

- **شاشة تحصيل موحدة**: اختر المستأجر ⇐ يظهر كشفه (أشهر مستحقة، جزئية، رصيد مقدم) ⇐ أدخل المبلغ والخزينة ⇐ اقتراح توزيع قابل
  للتعديل ⇐ تأكيد ⇐ سند قبض PDF. تُستبدل بها الطرق الثلاث الحالية (حوار التحصيل، ربط الأشهر بقيد، معاملة عامة).
- ربط شهر بقيد يدوياً يبقى للمحاسب فقط، مع سبب إلزامي، ويقتصر على قيود تحصيل نفس المستأجر.
- كشف حساب مستأجر (مدين/دائن/رصيد) PDF يطابق الدفتر سطراً بسطر، وبوابة المستأجر تعرض نفس الكشف.
- «سجل الإيجار» (Rent Roll): كل وحدة، مستأجرها، إيجارها، المستحق، المحصّل، المتأخر، تاريخ نهاية العقد.
- العقود: شاشة لإدخال الشروط الحقيقية (بداية، نهاية، إيجار، تأمين، زيادة، تجديد) بإدخالك — العقود الـ 68 الحالية تلقائية بمدة 10 سنوات ولن تُمس قبل ذلك.

### 3.4 القبول

كل سيناريوهات 3.2 ناجحة آلياً · `audit:integrity` بلا FAIL في الإيجار · رصيد الذمم في الدفتر = مجموع المتبقي على المطالبات − الأرصدة المقدمة · أعمار الذمم تساوي الواقع.

## 4. الموظفون والرواتب — ملف كامل، خصم، مكافأة، سلفة، وسجل دقيق

### 4.1 ملف الموظف

البيانات الأساسية والوظيفية · هيكل الراتب (أساسي + بدلات: سكن، نقل، أخرى) بتاريخ سريان · الحالة (نشط/موقوف/منتهٍ) وتاريخها ·
المستندات (عقد، هوية) · **سجل زمني غير قابل للحذف**: كل تغيير (راتب، وظيفة، حالة، خصم، مكافأة، سلفة) بمن غيّره ومتى ولماذا وقيمته قبل/بعد.

### 4.2 الحركات

| الحركة | التفاصيل | القيد المحاسبي |
|---|---|---|
| **مكافأة** | مبلغ، شهر الاستحقاق، سبب، اعتماد | مدين مصروف مكافآت / دائن رواتب مستحقة |
| **خصم** | نوع (غياب بعدد أيام، جزاء، خصم إداري)، مبلغ أو أيام تُحوَّل لمبلغ، سبب، اعتماد | الغياب يُنقص المصروف؛ الجزاء دائن «إيرادات أخرى — جزاءات» |
| **سلفة** | مبلغ، عدد أقساط، قسط شهري يُستقطع تلقائياً، رصيد متبقٍ ظاهر | صرف: مدين سلف الموظفين (أصل) / دائن الخزينة؛ الاستقطاع: دائن سلف الموظفين |
| عمل إضافي / بدل مؤقت | ساعات × معدل أو مبلغ | مدين مصروف / دائن رواتب مستحقة |

كل حركة: **مسودة ⇐ اعتماد (المالك/المدير) ⇐ تدخل كشف الشهر**. الحركة المعتمدة لا تُعدَّل؛ تُلغى بحركة عكسية — نمط Odoo حيث لا يدخل الكشف إلا ما اعتُمد.

### 4.3 كشف الرواتب الشهري

شاشة واحدة لكل الموظفين: الأساسي + البدلات + المكافآت − الخصومات − أقساط السلف = **الصافي**، مع تمييز أي فرق عن الشهر السابق.
مراجعة ⇐ اعتماد ⇐ ترحيل (مدين مصروفات الرواتب / دائن رواتب مستحقة / دائن سلف) ⇐ صرف (من خزينة واحدة أو لكل موظف) ⇐ كشف راتب PDF
لكل موظف + كشف رواتب مجمع PDF. لا يُرحَّل الشهر مرتين.

### 4.4 تقارير

سجل الرواتب الشهري · كشف حساب موظف · السلف القائمة · تكلفة الرواتب حسب القسم · مقارنة شهرية · الإجمالي السنوي لكل موظف.

### 4.5 ترحيل البيانات القائمة (بموافقتك)

إنشاء ملفات الموظفين بإدخالك، ثم ربط الـ 16 دفعة رواتب الحالية (253,168 د.ل) كـ «رواتب تاريخية» دون تغيير أي مبلغ أو قيد.
مع توحيد بندي `EXP-SAL` و`EXP-SLR` في بند واحد.

## 5. الموردون — ذمم دائنة حقيقية

- **فاتورة مورد**: رقم الفاتورة، تاريخها، تاريخ الاستحقاق، بنود بمصروفاتها، مرفق الصورة. القيد: مدين المصروف / دائن الموردين.
- **سداد مورد**: كلي أو جزئي، لفاتورة أو عدة فواتير. القيد: مدين الموردين / دائن الخزينة. يبقى المصروف النقدي المباشر للمصروفات الصغيرة.
- كشف حساب مورد + **أعمار ذمم الموردين** + تنبيه بالفواتير المستحقة هذا الأسبوع.
- **فواتير متكررة**: الكهرباء والمياه، وإيجار المول للمالكين (553,035 د.ل لـ 5 مالكين) بجدول دفعات — نفس محرك الإيجار بالاتجاه المعاكس.
- منع تكرار فاتورة (نفس المورد + نفس الرقم)، واعتماد للمبالغ فوق حد تحدده، ومطابقة أمر الشراء والاستلام للمشتريات الكبيرة فقط.
- **تنظيف البيانات**: أداة لإسناد الـ 210 مصروفاً بلا مورد دفعة واحدة مع اقتراح المورد من الوصف؛ نقل الـ 11 مصروفاً المسجلة على عملاء.
- إلزام اختيار المورد للمصروفات فوق حد محدد من الآن فصاعداً.
- أرشفة المورد بدل حذفه (الحذف اليوم يفصل تاريخ معاملاته).

## 6. العملاء — إيرادات غير الإيجار

- فواتير عملاء للمواقف والفعاليات والإعلانات والأكشاك، بتاريخ استحقاق وسداد كلي/جزئي.
- عقود متكررة للأكشاك والإعلانات (تعيد استخدام محرك الإيجار مع أنواع وحدات).

### 9.3 العربية والاتجاه (من فحص RTL)

- تحويل 186 محاذاة و75 هامشاً و25 موضعاً فيزيائياً إلى خصائص منطقية (`text-start/end`، `ms/me`، `ps/pe`، `start/end`).

- لفّ التطبيق بـ `DirectionProvider` حتى تنعكس أسهم لوحة المفاتيح في القوائم والتبويبات.
- تثبيت التنسيق: `ar-LY-u-nu-latn` للأرقام والتقويم الميلادي، والدينار بثلاث خانات عبر `Intl` في كل الشاشات وملفات PDF.
- الهاتف والأرقام والمراجع داخل `<bdi>`؛ حقول الهاتف والمبالغ `dir="ltr"`.
- أهداف لمس لا تقل عن 44 بكسل، وتباين ألوان AA.
