## 1. المسار السريع (إن كان الجهاز جاهزاً)

```powershell
git clone https://github.com/mturke1996/TajMall.git C:\dev\TajMall
cd C:\dev\TajMall
git checkout claude/vibrant-edison-r4u632
npm ci
npm run preflight      # يفحص الجهاز ويقول ماذا ينقص
```

### 2.2 قبل أن تبدأ (يمنع معظم المشاكل)

- **ضع المشروع في `C:\dev\TajMall`** وليس داخل OneDrive أو Desktop أو Documents (المزامنة تقفل ملفات `node_modules` فتفشل `npm ci`).
- استعمل **Windows Terminal** (يعرض العربية سليمة)، لا نافذة PowerShell القديمة.
- إن ظهر «running scripts is disabled on this system» شغّل مرة واحدة:
  `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`
- استثنِ مجلد المشروع من مضاد الفيروسات إن كان `npm ci` أو البناء بطيئاً جداً.

### 2.3 ملف `.env.local` (يلزم لسكربتات القاعدة وللتشغيل المحلي)

```powershell
copy .env.example .env.local
notepad .env.local
```

املأ القيم من لوحة Supabase. **لا ترسل هذا الملف لأحد، ولا تنسخ قيمه إلى مكان آخر.** (`.gitignore` يمنع رفعه، و`preflight` يتأكد.)

| المتغير | من أين | يلزم لـ |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project Settings ← API ← Project URL | تشغيل التطبيق محلياً |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (أو `…ANON_KEY`) | Project Settings ← API | تشغيل التطبيق محلياً |
| `SUPABASE_SECRET_KEY` | Project Settings ← API (المفتاح السري) | دعوة المستخدمين وبوابة المستأجر محلياً. **اختياري**، ولا تضعه في أي مكان آخر |
| `DATABASE_URL` أو `DIRECT_URL` | Project Settings ← Database ← Connection string | **سكربتات القاعدة**: `db:snapshot`، `audit:*`، الاستعادة |

ملاحظات الاتصال بالقاعدة:

- السكربتات تقرأ `DATABASE_URL` أولاً ثم `DIRECT_URL`. إن فشل الاتصال بخطأ مثل `ENETUNREACH` فشبكتك بلا IPv6 وعنوان الاتصال المباشر IPv6 فقط: استعمل **Session pooler** (أو Transaction pooler) كما في `.env.example`.
- إن كانت كلمة المرور فيها `@` أو `#` أو `:` فرمّزها (`%40` بدل `@`).
- بعد تدوير كلمة مرور القاعدة (المرحلة 0) حدّث هذا الملف بالجديدة.

### 2.4 تشغيل التطبيق محلياً (اختياري)

```powershell
npm run dev        # ثم افتح http://localhost:3000
```

> **تحذير**: التطبيق المحلي يتصل بمشروع Supabase المكتوب في `.env.local`، أي **الإنتاج الحقيقي** إن وضعت مفاتيحه. أي إدخال تجريبي تسجّله من الشاشة يُكتب في الدفتر الحقيقي. تصفّح فقط، أو استعمل مشروعاً تجريبياً منفصلاً للتجارب.
> **المرحلتان 0 و1 لا تحتاجان تشغيل التطبيق محلياً أبداً.**

### غلاف سطح المكتب على ويندوز (W1) — تجربتك اليدوية

هذا ما **لم أستطع تجربته** (لا واجهة رسومية ولا ويندوز عندي). الكود مُختبَر بـ12 اختبار Rust وclippy؛ الباقي تجربة منك:

2. [ ] في النافذة اضغط F12 ← Console وشغّل:
      `await window.__TAURI__.core.invoke('get_shell_info')`
      **المتوقع**: كائن فيه `shellVersion` و`ipcProtocol: 1` وستة أسماء أوامر.
3. [ ] اختبار الأمان: `await window.__TAURI__.core.invoke('export_backup_copy', { id: '../x' })`
      **المتوقع**: خطأ «معرّف النسخة الاحتياطية غير صالح» (وليس محاولة قراءة ملف).
4. [ ] سجّل الدخول بحساب مالك/مدير ← الإعدادات ← النسخ الاحتياطي ← **إنشاء نسخة**. **المتوقع**: نجاح، وفي `%APPDATA%\ly.tajmall.fluxen\backups\` ملفات `<id>.zip` و`<id>.sqlite` و`index.json` **وبلا** ملفات `.part` أو `.tmp`.
5. [ ] تحقق من ZIP: `npm run backup:restore-cold -- "<مسار الـ zip>" --verify-only` ← `Archive is intact`.
6. [ ] زر «تصدير نسخة» ← حوار الحفظ ← احفظ ← تحقق من النسخة المصدَّرة بنفس الأمر.
7. [ ] شغّل `npm run tauri:dev` مرة ثانية والنافذة الأولى مفتوحة. **المتوقع**: لا نافذة ثانية؛ الأولى تظهر وتأخذ التركيز.
8. [ ] `npm run tauri:build` ← ثبّت المثبّت الناتج (`src-tauri\target\release\bundle\msi` أو `…\nsis`) ← شغّله. **المتوقع**: يفتح تطبيق الإنتاج، ويعمل تسجيل الدخول وصفحة النسخ الاحتياطي. (المثبّت غير موقّع: سيظهر تحذير SmartScreen، وهذا متوقع لحين W1.)
9. [ ] **أرسل لي** نتيجة كل بند (نجح/فشل + نص الخطأ).

## 5. إن فشل شيء (ويندوز)

| العَرَض | السبب المرجّح | الحل |
|---|---|---|
| `npm ci` يفشل بـ `EBUSY` أو `EPERM` | مزامنة OneDrive أو مضاد فيروسات | انقل المشروع إلى `C:\dev\TajMall`، واستثنِه من المضاد |
| `running scripts is disabled` | سياسة PowerShell | `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` |
| العربية مقلوبة أو رموز غريبة في الطرفية | نافذة قديمة | استعمل Windows Terminal |
| `npm run dev` يقول إن المنفذ 3000 مشغول | عملية سابقة | `npm run free-port` |
| `db:snapshot` يفشل بـ `ENETUNREACH` أو انتهاء مهلة | الاتصال المباشر IPv6 فقط | ضع **Session pooler** في `DATABASE_URL` |
| `link.exe not found` أو أخطاء `cargo` عند `tauri:dev` | ينقص Visual Studio Build Tools | ثبّت «Desktop development with C++»، وأعد فتح الطرفية |
| `tauri:build` يتعطل عند تنزيل WiX أو NSIS | شبكة أو وكيل | أعد المحاولة، أو جرّب شبكة أخرى |
| `npm run ci:local` يفشل `test:hardening` أو `verify:rent-allocation` **بعد 1 يناير 2027** | هذه الاختبارات القديمة تعتمد على التاريخ (دَين N-16 في الخطة)؛ CI يثبّت الساعة، وجهازك لا | ليس تراجعاً. إعادة كتابتها بساعة اختبار مشتركة مسجَّلة. للتجربة استعمل WSL مع `faketime` |
| `ci:local --with-build` يفشل في اختبار المتصفح | لا يوجد Edge/Chrome | يستعمل Edge على ويندوز؛ اضبط `PW_CHANNEL=chrome` إن لزم |
| تحذير `LF will be replaced by CRLF` | إعداد Git على ويندوز | غير ضار: `.gitattributes` يثبّت LF |
| `npm audit` يعرض ثغرات «moderate» في أدوات التطوير | `minimatch` عبر `eslint-config-next` | معروفة ومقبولة مؤقتاً (الخطة: F-18)؛ بوابة CI على الإنتاج فقط |

## 6. قواعد لا تُكسر

1. **نسخة جديدة ومتحقَّق منها** (`db:snapshot` ثم `--verify-only`، ونسخة ثانية خارج الجهاز) قبل **أي** تغيير على القاعدة.
2. **هجرة واحدة في كل مرة.** بعد كل واحدة: `audit:security` و`audit:integrity` واختبار الأدوار. وإن بدا شيء خاطئاً فـ`ROLLBACK` الأخير فوراً.
3. **لا أسرار في المحادثات ولا الملفات ولا الـ commits.** المفتاح الذي نُشر سابقاً يُعامَل كمسروق حتى يُبطَل.
4. **لا إدخال تجريبي على الإنتاج** بمفاتيحه.
5. **لا تعديل لبيانات تاريخية** (عقد، دفعة، قيد) دون معاينة بالأرقام وموافقتك المكتوبة.
6. **لا `npm audit fix --force`، ولا ترقية حزمتين معاً.**
7. **القرارات المعلّقة** (الخطة، القسم 9) تُتخذ قبل المرحلة 3؛ لا يتخذها الوكيل بدلاً منك (تأمين العقد، الإلغاء بدل الحذف، الخطة المدفوعة…).

## 7. ماذا ترسل لي بعد كل مرحلة

| بعد | الصق |
|---|---|
| القسم 1 | ناتج `npm run preflight`، وآخر سطرين من `npm run ci:local` |
| طلب الدمج | حالة CI، ونص أي خطوة حمراء |
| المرحلة 0 | نتيجة الملحق أ، وهل المستودع عام، وقرار الخطة المدفوعة |
| كل هجرة | سطر `audit:integrity` قبل/بعد، وأي `FAIL`، ونتيجة اختبار الأدوار |
| تجربة ويندوز (W1) | نتيجة البنود 1–9 |

كلما أرسلت شيئاً من هذه أستطيع أن أحدّد لك الخطوة التالية بدقة، أو أصلح ما فشل.
